01 Latar Belakang & Tantangan Bisnis
🏪 Konteks & Budaya Bisnis Lokal

UD ABANG ADIK adalah toko sepatu, sandal, dan tas sekolah di Pasar Horas, Pematangsiantar yang berdiri sejak 1998. Transaksi tradisional sangat bertumpu pada tawar-menawar dan hubungan akrab dengan pedagang, hal yang kerap hilang pada sistem e-commerce keranjang belanja konvensional.

🎯 Tantangan Rekayasa & Operasional

Digitalisasi harus mempertahankan interaksi tawar-menawar tanpa biaya server bulanan (*Zero-Cost Constraint*). Sistem harus tetap beroperasi mulus (*high availability*) meskipun terjadi gangguan jaringan atau database di pasar tradisional.

02 Inovasi Fitur Utama
⚡ Dynamic BargainMeter

Algoritma interaktif yang mengkalkulasi rasio diskon harga tawar terhadap harga resmi retail. Menyajikan visual meter dan advice psikologis secara instan (Sadis, Sengit, Bersahabat, Wajar, Dermawan) sebelum diajukan.

💬 WhatsApp Conversational Checkout

Konversi tawaran menjadi payload pesan WhatsApp Click-to-Chat otomatis berisi detail nama produk, ukuran kaki, kuantitas, dan harga tawar. Menghilangkan friksi checkout dan langsung menghubungkan pembeli ke penjual.

🔐 Double Gatekeeper Security

Perlindungan akses admin dua lapis: gerbang modal kode rahasia di client-side (*front-gate modal*) sebelum form login backend dibuka, diperkuat oleh validasi JWT dan enkripsi password bcrypt di server.

📦 Real-Time Admin Inventory Portal

Dashboard manajemen inventaris penuh (CRUD) dengan unggah gambar instan, manajemen kategori, filter status produk terlaris (*best seller*), serta sinkronisasi dinamis ke TiDB Cloud.

04 Tantangan Rekayasa & Solusi Teknis
1. Menembus Batasan Read-Only Filesystem (Vercel EROFS) Serverless Storage
Tantangan: Serverless runtime Vercel bersifat ephemeral dan melarang penulisan ke disk (error EROFS pada upload disk tradisional).
Solusi: Menggunakan multer.memoryStorage() dan mengonversi buffer gambar ke format Base64 Data URI, disimpan langsung ke kolom MEDIUMTEXT database TiDB. Menghilangkan kebutuhan cloud storage berbayar (AWS S3) dan menghemat biaya hingga 100%.
2. Graceful Degradation: Circuit Breaker & In-Memory Fallback High Availability
Tantangan: Fluktuasi koneksi database cloud atau uji coba lokal tanpa internet dapat menyebabkan server mengalami crash (500 Error) dan katalog mati.
Solusi: Membangun emulator SQL in-memory (executeMemoryQuery) di db.js sebagai fallback otomatis. Jika koneksi TiDB terputus, backend secara mulus beralih ke in-memory store tanpa memutus proses pengguna (100% uptime).
3. TLS/SSL Handshake & Monorepo SPA Routing di Serverless Cloud & DevOps
Tantangan: Koneksi TiDB Cloud membutuhkan sertifikat TLS 1.2+, dan monorepo Vercel harus melayani SPA Vite sekaligus serverless API tanpa konflik routing.
Solusi: Mengimplementasikan certificate resolver yang membaca DB_CA_CERT dari environment variable, serta mengonfigurasi routing matrix vercel.json dengan asset rewrites dan wildcard SPA fallback.
